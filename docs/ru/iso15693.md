# Метки ISO15693

*[In English](../en/iso15693.md)*

Метки дальнего действия (vicinity), такие как ICODE SLIX, SLIX2, DNA, и метки многих библиотек и прачечных: дальность
больше, чем у ISO14443A, память из блоков, аутентификации в этом драйвере нет.

```c
#include "pn5180-15693.h"

pn5180_proto_t *tags = pn5180_15693_init(pn5180, PN5180_15693_26KASK100);
tags->setup_rf(tags);

pn5180_uids_array_t *found = tags->get_all_uids(tags);
if (found != NULL && tags->select_by_uid(tags, &found->uids[0])) {
    int blocks = 0, block_size = 0;
    tags->detect_card_type_and_capacity(pn5180, &found->uids[0], &blocks, &block_size);
    uint8_t data[32];
    if (block_size <= (int)sizeof(data) && tags->block_read(tags, 0, data, block_size)) {
        ESP_LOG_BUFFER_HEX(TAG, data, block_size);
    }
    tags->halt(tags);
}
free(found);
```

## Конфигурация RF

`pn5180_15693_init()` принимает конфигурацию RF, которую загружает `setup_rf()`: `PN5180_15693_26KASK100` (26 кбит/с,
ASK 100 %) или `PN5180_15693_26KASK10` (ASK 10 %). `PN5180_15693_26KASK100` подходит большинству меток.

Инвентаризация от этого выбора не зависит: сначала она идёт с ASK 10 %, при которой метки лучше получают питание во
время модуляции, и переходит на ASK 100 %, только если ничего не нашла. Конфигурация, на которой она закончила, остаётся
загруженной, и выбор, чтение и запись работают с ней.

После включения поля драйвер выжидает защитное время, по умолчанию 5,1 мс. Меткам ISO15693 нужна 1 мс; программа,
которая опрашивает только ISO15693, может сократить его через `pn5180_set_rf_guard_time_us(pn5180, 1000)`.

## Инвентаризация

`get_all_uids()` и `pn5180_15693_get_all_uids_ex()` проводят инвентаризацию с маской, по одному слоту на запрос: при
коллизии маска растёт на один бит и пробуются оба значения. Каждой найденной метке посылается Stay Quiet, чтобы она
больше не отвечала, а когда проход нашёл метки, всё поле опрашивается ещё раз, чтобы нашлась и слабая метка за сильной.
Инвентаризация останавливается после 192 кадров, этого хватает примерно на 50 меток с непохожими UID. Подробности — на
странице [Поиск карт](polling.md#iso15693).

Элементы приходят отсортированными по силе сигнала, сильнейший первым (наименьший `agc`). В UID 8 байт, младший первым:
`uid[7]` — это `E0`, `uid[6]` — код производителя (04h у NXP).

Опрос не сообщает `PN5180_POLL_PROTOCOL_ERROR`: ответы, которые пришли повреждёнными или столкнулись и не разрешились,
дают `PN5180_POLL_NO_TARGET`, потому что PN5180 сообщает о шуме так же.

## Выбор, определение, остановка

- `select_by_uid()` посылает Select, адресованный UID элемента; метка переходит в состояние Selected, и следующие
  команды посылаются выбранной метке.
- `detect_card_type_and_capacity()` посылает Get System Information и берёт из ответа число блоков и размер блока;
  `subtype` становится `PN5180_15693`. Метка, которая на эту команду не отвечает или не сообщает свою память, получает
  `block_size` 4 и `blocks_count` 0. Колбэк возвращает `false`: повторный выбор не нужен.
- `halt()` посылает Reset to Ready выбранной метке, и та возвращается в состояние Ready. В ISO15693 эта команда
  необязательна: на метке, которая её не поддерживает, `halt()` возвращает `false`, и метка остаётся выбранной до
  выключения поля.

Метка в состоянии Ready отвечает на следующую инвентаризацию: метку, которую выбрали или остановили, следующий опрос
считает снова, даже если поле осталось включённым.

## Блоки

```c
const uint8_t block[4] = {0x11, 0x22, 0x33, 0x44};
if (tags->block_write(tags, 5, block, sizeof(block)) == 0) {
    uint8_t back[4];
    tags->block_read(tags, 5, back, sizeof(back));
}
```

- `block_read()` посылает Read Single Block, а для номера блока больше 255 (до 65535) — Extended Read Single Block.
  Метка должна отдать не меньше `buffer_len` байт; передавать нужно размер блока, полученный при определении типа.
- `block_write()` посылает Write Single Block, а выше блока 255 — расширенную команду, с данными от 1 до 32 байт. Он
  возвращает 0, когда метка подтвердила запись, и отрицательное значение в остальных случаях. Метка отвечает после
  программирования, а оно может занять до 20 мс.
- `authenticate` у ISO15693 равен `NULL`: защита паролем, режим приватности и другие собственные (custom) команды меток
  ICODE не реализованы. Если они нужны, их можно посылать через `pn5180_rf_transceive()`.

NDEF на метке ISO15693 (NFC Forum Type 5) читают и пишут [функции NDEF](ndef.md): capability container в блоке 0, TLV
после него.
