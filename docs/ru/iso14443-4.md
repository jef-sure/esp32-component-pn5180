# ISO14443-4 и APDU

*[In English](../en/iso14443-4.md)*

DESFire, банковские карты, паспорта, JCOP и другие смарт-карты, а также телефоны в режиме эмуляции карты работают по
ISO14443-4 (ISO-DEP): считыватель посылает APDU-команды (ISO 7816-4), а карта отвечает APDU-ответами. Драйвер
работает только в режиме считывателя; эмуляция карты и режим peer-to-peer не реализованы.

```c
#include "pn5180-14443.h"
```

## Активация

Карту ISO14443-4 находит [опрос ISO14443A](polling.md), как и любую другую; в её SAK установлен бит `20`, и
`detect_card_type_and_capacity()` сообщает о ней как о `PN5180_MIFARE_DESFIRE`, какая бы это ни была карта.
`select_by_uid()` сама активирует уровень ISO14443-4 командой RATS:

- ответ (ATS) сообщает самый большой кадр, который принимает карта (FSCI), её время ожидания кадра (FWI) и её
  стартовое защитное время кадра (SFGI);
- драйвер выжидает стартовое защитное время кадра перед первым блоком;
- зарезервированное значение FWI 15 читается как значение по умолчанию 4, зарезервированное SFGI 15 — как 0,
  зарезервированное FSCI — как наибольший размер кадра.

Карта, которая ещё и эмулирует MIFARE Classic (SAK `28` или `38`), не активируется, если программа об этом не
попросит, см. [Карты с MIFARE Classic и ISO14443-4 сразу](iso14443a.md#карты-с-mifare-classic-и-iso14443-4-сразу).

## Обмен APDU

```c
const uint8_t apdu[] = {0x90, 0x60, 0x00, 0x00, 0x00}; /* DESFire GetVersion */
uint8_t       rx[64];
size_t        rx_len = sizeof(rx);
if (pn5180_14443_4_transceive(pn5180, apdu, sizeof(apdu), rx, &rx_len)) {
    pn5180_apdu_response_t response;
    pn5180_apdu_parse_response(rx, rx_len, &response);
    printf("SW %04X, %u data bytes\n", pn5180_apdu_get_status(&response), (unsigned)response.data_len);
}
```

`pn5180_14443_4_transceive()` посылает одну APDU-команду и возвращает весь ответ: данные, за ними SW1 SW2. `rx_len`
на входе — размер `rx`, на выходе — длина ответа. При этом драйвер:

- **разбивает на цепочку блоков** команду длиннее кадра карты (несколько I-block) и собирает ответ, пришедший
  цепочкой, блоками не больше 253 байт;
- **ждёт** каждый блок в течение времени ожидания кадра из ATS и даёт продление времени ожидания (S(WTX)) вплоть до
  самого долгого времени ожидания кадра, которое допускает стандарт, около 5 с; с картой, которая просит больше 10
  продлений подряд, обмен прекращается;
- **повторяет** блок, который потерялся или пришёл повреждённым, до 3 раз, через R(NAK) или повторной отправкой, как
  описывает ISO/IEC 14443-4.

`true` значит, что ответ пришёл; слово состояния в нём говорит, выполнила ли карта то, о чём её просили. Неудачный
обмен (нет ответа после повторов, ошибка протокола, ответ больше `rx`) завершает сессию: драйвер посылает
S(DESELECT), и перед следующей APDU-командой карту нужно снова выбрать через `select_by_uid()`. Если карта не
отзывается и на это, выключите и снова включите поле.

`halt()` отпускает карту командой S(DESELECT). Карта, оставленная в своей сессии, отвечала бы на I-block,
предназначенные следующей карте, поэтому `select_by_uid()` и опрос сначала сами закрывают такую сессию.

## SELECT и READ BINARY

Для двух команд ISO 7816-4 есть вспомогательные функции, потому что их использует код NDEF:

```c
static const uint8_t ndef_app[] = {0xD2, 0x76, 0x00, 0x00, 0x85, 0x01, 0x01};
static const uint8_t cc_file[]  = {0xE1, 0x03};

if (pn5180_14443_4_select_file(pn5180, ndef_app, sizeof(ndef_app)) &&
    pn5180_14443_4_select_file(pn5180, cc_file, sizeof(cc_file))) {
    uint8_t cc[15];
    size_t  got = sizeof(cc);
    if (pn5180_14443_4_read_binary(pn5180, 0, sizeof(cc), cc, &got)) {
        ESP_LOG_BUFFER_HEX(TAG, cc, got);
    }
}
```

- `pn5180_14443_4_select_file()` выбирает приложение по AID, если ей передано больше двух байт (P1 04h), или
  элементарный файл по его идентификатору (P1 00h, P2 0Ch, без данных в ответе), как требует схема размещения NFC
  Forum Type 4 версии 2.0. Карту, которая отклоняет выбор файла словом состояния с ошибкой, спрашивают ещё раз с
  P2 00h — для карт со схемой размещения 1.0. Функция возвращает `true` на ответ `90 00`.
- `pn5180_14443_4_read_binary()` читает из выбранного файла: `offset` — до 7FFFh, `le` — сколько байт запрошено,
  0 означает 256. `got` на входе — размер буфера, на выходе — число байт; если ответ не помещается, функция
  возвращает `false`, а в `got` лежит нужный ей размер.

## block_read на карте ISO14443-4

Для карты ISO14443-4 колбэк `block_read` — это READ BINARY по файлу, который программа выбрала последним, с номером
блока в роли смещения в файле и `buffer_len` (от 1 до 255) в роли Le. Он завершается ошибкой, если карта вернула
меньше байт, чем просит буфер, например в конце файла.

`block_write` для такой карты недоступен: он послал бы кадры MIFARE, которым не место в сессии ISO14443-4, поэтому
возвращает -1 и ничего не посылает. Вместо него пишите APDU-командой UPDATE BINARY через
`pn5180_14443_4_transceive()`. `authenticate` возвращает `true` и ничего не делает; аутентификация DESFire и других
карт — это последовательность APDU-команд из собственного набора команд карты, здесь она не реализована.

## Утилиты APDU

Эти функции не зависят ни от PN5180, ни от карты: они разбирают и собирают APDU в памяти вызывающего и ничего не
выделяют; указатели на данные после разбора указывают во входной буфер.

```c
pn5180_apdu_command_t cmd;
const uint8_t raw[] = {0x00, 0xA4, 0x04, 0x00, 0x07, 0xD2, 0x76, 0x00, 0x00, 0x85, 0x01, 0x01, 0x00};
if (pn5180_apdu_parse_command(raw, sizeof(raw), &cmd) == ESP_OK) {
    /* cmd.ins == 0xA4, cmd.data_len == 7, cmd.has_le, cmd.le == 256 */
}

uint8_t out[32];
size_t  out_len;
pn5180_apdu_build_response(out, sizeof(out), (const uint8_t *)"OK", 2, 0x90, 0x00, &out_len); /* 4F 4B 90 00 */
```

- `pn5180_apdu_parse_command()` принимает короткие APDU случаев 1, 2S, 3S и 4S; на APDU расширенной длины она
  возвращает `ESP_ERR_NOT_SUPPORTED`, на неверно построенную — `ESP_ERR_INVALID_ARG`. Le, закодированное нулём,
  возвращается как 256.
- `pn5180_apdu_parse_response()` делит ответ на данные и SW1 SW2; `pn5180_apdu_get_status()` возвращает их одним
  16-битным словом состояния.
- `pn5180_apdu_build_response()` записывает `DATA SW1 SW2` в буфер; если он слишком мал — `ESP_ERR_NO_MEM`.
- Константы слов состояния: `PN5180_APDU_SW_SUCCESS` (9000h), `PN5180_APDU_SW_WRONG_LENGTH` (6700h),
  `PN5180_APDU_SW_WRONG_P1P2` (6A86h), `PN5180_APDU_SW_INS_NOT_SUPPORTED` (6D00h),
  `PN5180_APDU_SW_CLA_NOT_SUPPORTED` (6E00h).

## Телефоны

Телефон в режиме эмуляции карты — цель ISO14443-4 со [случайным UID](polling.md#цели-со-случайным-uid): выбирайте и
используйте его в том же опросе, который его нашёл. Приложение на телефоне отвечает на AID, которые оно
зарегистрировало; приложение, эмулирующее метку NFC Forum Type 4, читается через `pn5180_ndef_read_card_auto()` как
карта, см. [NDEF](ndef.md).
