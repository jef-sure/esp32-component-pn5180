# Подключение, шина SPI и IRQ

*[In English](../en/hardware.md)*

Модуль, его пины и питание, своя шина SPI или общая с другими устройствами, пин IRQ, обнаружение карты с малым
потреблением и два считывателя рядом.

## Модуль

PN5180 общается с хостом по SPI и имеет ещё две собственные линии: **BUSY**, которую он поднимает, пока выполняет
команду, и **IRQ**, которая сообщает о событиях, например о конце радиообмена. RST его сбрасывает.

| Сигнал | Направление | Обязателен | Примечания |
| ------ | ----------- | ---------- | ---------- |
| SCK, MOSI | ESP32 → PN5180 | да | режим SPI 0, до 7 МГц |
| MISO | PN5180 → ESP32 | да | |
| NSS | ESP32 → PN5180 | да | выбор устройства (chip select); им управляет драйвер как обычным GPIO, а не периферия SPI |
| BUSY | PN5180 → ESP32 | да | драйвер ждёт нужного уровня до и после каждой передачи |
| RST | ESP32 → PN5180 | да | активный уровень низкий; `pn5180_init()` и `pn5180_reset()` подают на него импульс |
| IRQ | PN5180 → ESP32 | нет | нужен только для `pn5180_lpcd_wait()`; в остальном экономит время CPU |
| GPIO, AUX, REQ | | нет | не используются |

Распространённой плате модуля нужно 5 В для передатчика и 3,3 В для логики и выводов; GPIO ESP32 работают с логикой
3,3 В. Подайте оба питания. На 7 МГц провода должны быть короткими; с длинными проводами понизьте частоту.

Металл расстраивает антенну: модуль на металлической поверхности или рядом с металлическим корпусом находит карты
плохо или не находит совсем.

## Пины

Подойдут любые GPIO, со следующими ограничениями:

- NSS, RST, SCK и MOSI — выходы ESP32: GPIO, работающие только на вход, для них не годятся (GPIO 34–39 у классического
  ESP32).
- GPIO флеша и PSRAM заняты: 6–11 у классического ESP32, поэтому `examples/app_logic`, чьи пины 6–8 подходят для
  ESP32-S3, на классическом ESP32 не работает.
- Strapping-пины (GPIO 0, 2, 5, 12 и 15 у классического ESP32) работают, но уровень, который модуль выставит на них при
  включении питания, может изменить то, как загружается чип. GPIO 12, который `examples/simple_main` использует для
  RST, задаёт напряжение флеша классического ESP32: если с подключённым модулем плата не загружается, перенесите RST на
  другой GPIO.

`pn5180_spi_init()` и `pn5180_init()` проверяют свои пины, прежде чем обращаться к железу, и возвращают `NULL` для
пина, который не является GPIO этого чипа (в том числе `GPIO_NUM_NC`), или для выходного пина на GPIO, работающем
только на вход; пин назван в логе.

## Своя шина SPI

```c
/* SPI host, SCK, MISO, MOSI, clock */
pn5180_spi_t *spi    = pn5180_spi_init(SPI3_HOST, GPIO_NUM_18, GPIO_NUM_19, GPIO_NUM_23, 7000000);
/* NSS, BUSY, RST */
pn5180_t     *pn5180 = pn5180_init(spi, GPIO_NUM_5, GPIO_NUM_21, GPIO_NUM_12);
```

`pn5180_spi_init()` инициализирует шину с каналом DMA и добавляет на неё PN5180. Частота выше 7 МГц
(`PN5180_SPI_MAX_CLOCK_HZ`) понижается до 7 МГц. `pn5180_deinit(pn5180, true)` освобождает устройство и эту шину.

`pn5180_init()` сбрасывает PN5180, ждёт его загрузки (до 5 с), читает версию прошивки и возвращает `NULL`, если PN5180
не отвечает или сообщает прошивку старше 3.4. При неудаче структура SPI остаётся как была: можно снова вызвать
`pn5180_init()` или освободить её через `pn5180_spi_deinit(spi, true)`.

## Общая шина SPI

Если на шине есть и другие устройства, программа инициализирует её сама и подключает к ней PN5180:

```c
spi_bus_initialize(SPI2_HOST, &bus_config, SPI_DMA_CH_AUTO); /* your bus, your other devices */
pn5180_spi_t *spi    = pn5180_spi_attach(SPI2_HOST, 7000000);
pn5180_t     *pn5180 = pn5180_init(spi, GPIO_NUM_5, GPIO_NUM_21, GPIO_NUM_12);
```

- `pn5180_spi_attach()` работает сразу после `spi_bus_initialize()`, когда других устройств на хосте ещё нет.
- Шина должна пропускать целую передачу PN5180 за одну транзакцию: оставьте `max_transfer_sz` по умолчанию или задайте
  не меньше `PN5180_MAX_BUF_SIZE` (512) и используйте канал DMA, потому что шина без DMA ограничена 64 байтами. Для
  хоста, который пропускает меньше, `pn5180_spi_attach()` возвращает `NULL` и не оставляет на нём устройства PN5180.
- Команда PN5180 — это две передачи SPI, каждая обрамлена NSS. Драйвер занимает шину, только пока на NSS низкий
  уровень; пока PN5180 выполняет команду (на BUSY высокий уровень, до нескольких миллисекунд при включении поля), шиной
  могут пользоваться другие устройства.
- Шину, к которой PN5180 подключили, `pn5180_deinit()` не освобождает никогда, каким бы ни был его второй аргумент.

Каждому из двух PN5180 на одной шине нужен свой `pn5180_spi_attach()` и свои пины NSS, BUSY и RST.

## Пин IRQ

```c
pn5180_irq_attach(pn5180, GPIO_NUM_4);
```

Необязательный вызов, один раз после `pn5180_init()`. С пином IRQ драйвер спит, пока PN5180 не сообщит о конце обмена;
без него драйвер опрашивает регистр состояния IRQ по SPI: первые 5 мс подряд, без пауз, затем раз в миллисекунду,
отпуская CPU между запросами. Полярность пина читается из EEPROM PN5180 (`IRQ_PIN_CONFIG`). Для пина, который не
является GPIO этого чипа, `pn5180_irq_attach()` возвращает `false`, и драйвер продолжает опрашивать регистр.

Для `pn5180_lpcd_wait()` пин IRQ обязателен.

## Обнаружение карты с малым потреблением

В режиме LPCD PN5180 спит и с заданным интервалом ненадолго включает поле; когда антенна замечает изменение — карту
или кусок металла, — он просыпается и поднимает IRQ.

```c
pn5180_irq_attach(pn5180, GPIO_NUM_4);
pn5180_lpcd_prepare(pn5180);          /* once: writes the LPCD settings to EEPROM if they differ */

while (true) {
    pn5180_lpcd_enter(pn5180, 500);   /* check for a card every 500 ms */
    if (pn5180_lpcd_wait(pn5180, -1, NULL)) {
        proto->setup_rf(proto);       /* woke up: a card or metal object is near */
        /* poll, read, halt ... */
        pn5180_set_rf_off(pn5180);
    }
}
```

- `pn5180_lpcd_prepare()` записывает настройки LPCD в EEPROM PN5180: высокую чувствительность и самокалибровку. Байт
  записывается, только если он отличается, потому что у EEPROM ограниченное число циклов записи; вызывайте её один раз
  при запуске.
- `pn5180_lpcd_enter()` принимает интервал в миллисекундах, от 1 до 2690 (`PN5180_MAX_WAKEUP_COUNTER_MS`). На прошивке
  3.A и новее она сначала даёт PN5180 измерить опорное значение антенны, поэтому входить в LPCD нужно, когда рядом с
  антенной нет карты.
- `pn5180_lpcd_wait()` ждёт, не трогая SPI, потому что любое обращение по SPI завершает режим LPCD; поэтому ей и нужен
  пин IRQ. Она возвращает `true`, когда PN5180 проснулся из-за карты или металла, и `false` по тайм-ауту (PN5180 всё ещё
  в режиме LPCD), при другой причине пробуждения или без пина IRQ. После пробуждения PN5180 теряет настройки регистров:
  `pn5180_lpcd_wait()` заново загружает конфигурацию RF, а поле остаётся выключенным до `setup_rf()` или
  `pn5180_set_rf_on()`.
- Чувствительность высокая, и разбудить его могут и металлический предмет или рука возле антенны. После каждого
  пробуждения выполняйте опрос и возвращайтесь в LPCD, если ничего не найдено.
- Чтобы выйти из режима LPCD без пробуждения, например после тайм-аута, вызовите `pn5180_recover()`: она сбрасывает
  PN5180 и восстанавливает конфигурацию RF.

## RFCA и два считывателя

Защита от столкновения полей (RFCA) по умолчанию включена: PN5180 не включает своё поле, пока обнаруживает чужое, и
`setup_rf()` завершается неудачей со строкой в логе `RF_ON blocked by external RF field (RFCA)`. С
`pn5180_set_rfca(pn5180, false)` поле включается, несмотря на чужое.

Двум считывателям с близко расположенными антеннами приходится включать поле по очереди: каждый мешает картам в поле
другого, а при включённой RFCA считыватель не включит своё поле, пока включено поле другого. Завершайте каждый цикл
вызовом `pn5180_set_rf_off()`. У каждого считывателя свой `pn5180_t`, и каждый может работать в своей задаче, в том
числе на одной шине SPI; создавайте и удаляйте их из одной задачи.

## EEPROM и регистры

`pn5180_read_eeprom()` читает EEPROM PN5180, например его версии:

```c
uint8_t version[2];
if (pn5180_read_eeprom(pn5180, PN5180_FIRMWARE_VERSION, version, sizeof(version))) {
    printf("firmware %d.%d\n", version[1], version[0]);
}
```

`PN5180_PRODUCT_VERSION`, `PN5180_FIRMWARE_VERSION` и `PN5180_EEPROM_VERSION` занимают по 2 байта, младший номер
версии первым. Версия прошивки, прочитанная при инициализации, хранится и в `pn5180->firmware_version`, старший
номер — в старшем байте.

`pn5180_write_eeprom()` пишет по адресам от 16h (`PN5180_EEPROM_MIN_ADDR`) до FEh; байты ниже хранят идентификационные
данные чипа. Регистры читают и пишут `pn5180_read_register()`, `pn5180_write_register()`,
`pn5180_write_register_or_mask()` и `pn5180_write_register_and_mask()`; адреса и биты — в `pn5180.h` с префиксом
`PN5180_`. Регистр, записанный программой, драйвер может перезаписать при следующей настройке RF; байт EEPROM
остаётся.
