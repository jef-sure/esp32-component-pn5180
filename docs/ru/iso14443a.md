# Карты ISO14443A

*[In English](../en/iso14443a.md)*

Карты MIFARE Classic, MIFARE Plus, Ultralight, NTAG и ISO14443-4: как драйвер их различает, выбирает, проходит на них
аутентификацию, читает и пишет их память. Картам ISO14443-4 и APDU посвящена [отдельная страница](iso14443-4.md),
опрос описан на странице [Поиск карт](polling.md).

```c
#include "pn5180-14443.h"

pn5180_proto_t *proto = pn5180_14443_init(pn5180, 0); /* 0: at most 14 cards per poll */
proto->setup_rf(proto);
```

## Типы карт

`detect_card_type_and_capacity()` берёт SAK выбранной карты (биты 0–6), а у семейства Ultralight спрашивает саму
карту:

| SAK | `subtype` | `blocks_count` × `block_size` |
| --- | --------- | ----------------------------- |
| `00` | семейство Ultralight, см. ниже | страницы по 4 байта |
| `08` | `PN5180_MIFARE_CLASSIC_1K` | 64 × 16 |
| `09` | `PN5180_MIFARE_CLASSIC_MINI` | 20 × 16 |
| `10` | `PN5180_MIFARE_PLUS_2K` (уровень безопасности 2) | 128 × 16 |
| `11` | `PN5180_MIFARE_PLUS_4K` (уровень безопасности 2) | 256 × 16 |
| `18` | `PN5180_MIFARE_CLASSIC_4K` | 256 × 16 |
| `28` | `PN5180_MIFARE_CLASSIC_1K`, эмуляция на карте ISO14443-4 | 64 × 16 |
| `38` | `PN5180_MIFARE_CLASSIC_4K`, эмуляция на карте ISO14443-4 | 256 × 16 |
| `20` или любой другой с битом `20` | `PN5180_MIFARE_DESFIRE`: карта ISO14443-4 | 0 × 1 |
| любой другой | `PN5180_MIFARE_UNKNOWN` | 0 × 0 |

`PN5180_MIFARE_DESFIRE` обозначает любую карту ISO14443-4, будь то DESFire, банковская карта, паспорт или телефон;
драйвер их не различает.

У всего семейства Ultralight один и тот же SAK `00` и ATQA `44 00`. Драйвер отправляет GET_VERSION (60h) и берёт из
ответа размер памяти и тип продукта:

| GET_VERSION | `subtype` | страницы |
| ----------- | --------- | -------- |
| размер памяти `0B`, продукт NTAG | `PN5180_MIFARE_NTAG210` | 20 |
| размер памяти `0B`, другой продукт | `PN5180_MIFARE_ULTRALIGHT_EV1` (MF0UL11) | 20 |
| размер памяти `0E`, продукт NTAG | `PN5180_MIFARE_NTAG212` | 41 |
| размер памяти `0E`, другой продукт | `PN5180_MIFARE_ULTRALIGHT_EV1` (MF0UL21) | 41 |
| размер памяти `0F` | `PN5180_MIFARE_NTAG213` | 45 |
| размер памяти `11` | `PN5180_MIFARE_NTAG215` | 135 |
| размер памяти `13` | `PN5180_MIFARE_NTAG216` | 231 |
| другой размер памяти | `PN5180_MIFARE_ULTRALIGHT` | 16 |
| нет ответа, а на AUTHENTICATE (1Ah) карта отвечает вызовом (challenge) | `PN5180_MIFARE_ULTRALIGHT_C` | 44 |
| нет ответа ни на одну из двух команд | `PN5180_MIFARE_ULTRALIGHT` | 16 |

Если ответ на GET_VERSION пришёл повреждённым, команда повторяется ещё один раз. Метка, которая не отвечает на
GET_VERSION, — первый Ultralight или NTAG203, — определяется как `PN5180_MIFARE_ULTRALIGHT` с 16 страницами; это лишь
догадка, поэтому функции NDEF берут размер её области данных только из capability container. Из 48 страниц
Ultralight C считаются 44, до которых достаёт READ; страницы ключа 2Ch–2Fh прочитать нельзя.

Определение карты семейства Ultralight оставляет её остановленной, и `detect_card_type_and_capacity()` возвращает
`true`: перед работой карту нужно выбрать снова. Для остальных карт функция возвращает `false`, и карта остаётся
выбранной.

```c
pn5180_uid_t *card = &cards->uids[i];
if (proto->select_by_uid(proto, card)) {
    int blocks = 0, block_size = 0;
    if (proto->detect_card_type_and_capacity(proto->pn5180, card, &blocks, &block_size)) {
        proto->select_by_uid(proto, card);
    }
    /* card->subtype, card->blocks_count and card->block_size are set */
}
```

## Выбор и остановка

`select_by_uid()` отправляет WUPA, которая будит карты и в состоянии IDLE, и остановленные, затем SELECT на каждом
уровне каскада с UID элемента. Она обновляет `sak` и `atqa` элемента. Карта с битом SAK `20` затем активируется как
карта ISO14443-4 (RATS), кроме карты, которая ещё и эмулирует MIFARE Classic, см.
[ниже](#карты-с-mifare-classic-и-iso14443-4-сразу).

`halt()` отправляет HLTA, а карте в её сессии ISO14443-4 — S(DESELECT). Остановленную карту `select_by_uid()` находит
снова, а опрос — только после того, как поле выключали.

Выбранная карта не отвечает на новый `select_by_uid()`: сначала её нужно остановить через `halt()`. Карта, отказавшая в
команде, выходит из выбранного состояния: Ultralight и NTAG — после любого NAK (чтение за последней страницей, запись в
заблокированную страницу), MIFARE Classic — после отказа в аутентификации. Тогда снова `halt()` и `select_by_uid()`.

## MIFARE Classic

### Память

Карта MIFARE Classic разделена на секторы, у каждого свои ключи:

| Карта | Секторы | Блоки |
| ----- | ------- | ----- |
| Mini | 5 по 4 блока | 0–19 |
| 1K | 16 по 4 блока | 0–63 |
| 4K | 32 по 4 блока, затем 8 по 16 блоков | 0–127, 128–255 |

Последний блок каждого сектора — его трейлер: ключ A, биты доступа, байт общего назначения и ключ B. Блок 0 — блок
производителя с UID. Трейлер записывают только с проверенными битами доступа: неверные навсегда блокируют сектор.

```c
static int first_block_of_sector(int sector)
{
    return sector < 32 ? sector * 4 : 128 + (sector - 32) * 16;
}
```

### Аутентификация

```c
static const uint8_t key[6] = {0xFF, 0xFF, 0xFF, 0xFF, 0xFF, 0xFF};

/* Card selected. Authentication is per sector: block 4 is the first block of sector 1. */
if (proto->authenticate(proto, key, PN5180_MIFARE_CLASSIC_KEYA, card, 4)) {
    uint8_t data[16];
    if (proto->block_read(proto, 4, data, sizeof(data))) {
        ESP_LOG_BUFFER_HEX(TAG, data, sizeof(data));
    }
}
```

- `key_type` — `PN5180_MIFARE_CLASSIC_KEYA` (60h) или `PN5180_MIFARE_CLASSIC_KEYB` (61h); номер блока, от 0 до 255,
  задаёт сектор. От UID из 7 или 10 байт в аутентификации участвуют последние 4 байта.
- После неудачной аутентификации карта перестаёт отвечать: перед следующим ключом её нужно выбрать снова (`halt()`,
  затем `select_by_uid()`).
- Один ключ — одна аутентификация: повторять тот же ключ после отказа значит только терять время. Карта, которая не
  ответила, ушла из поля, и следующий ключ до неё тоже не дойдёт.
- Для Ultralight, NTAG и карт ISO14443-4 `authenticate()` сразу возвращает `true` и ничего не отправляет. Картам
  MIFARE Plus отправляется та же аутентификация Crypto1, что и картам Classic.

`pn5180->iso14443_last_auth_status` говорит, почему аутентификация не удалась:

| Значение | Смысл |
| -------- | ----- |
| `PN5180_MIFARE_AUTH_OK` (0) | ключ принят |
| `PN5180_MIFARE_AUTH_REFUSED` (1) | карта отвергла ключ |
| `PN5180_MIFARE_AUTH_NO_ANSWER` (2) | карта не ответила: ушла из поля или не была выбрана |
| `PN5180_MIFARE_AUTH_NONE` (-1) | ничего не отправлено: номер блока или длина UID, которых протокол не знает |

Перебор списка ключей, как это делает `examples/app_logic`:

```c
static bool try_keys(pn5180_proto_t *proto, pn5180_uid_t *card, int block,
                     const uint8_t (*keys)[6], size_t key_count)
{
    for (size_t k = 0; k < key_count; k++) {
        for (uint8_t type = PN5180_MIFARE_CLASSIC_KEYA; type <= PN5180_MIFARE_CLASSIC_KEYB; type++) {
            if (proto->authenticate(proto, keys[k], type, card, block)) {
                return true;
            }
            if (proto->pn5180->iso14443_last_auth_status != PN5180_MIFARE_AUTH_REFUSED) {
                return false; /* the card is gone */
            }
            if (!proto->select_by_uid(proto, card)) {
                return false;
            }
        }
    }
    return false;
}
```

### Блоки

После аутентификации сектора с его блоками работают `block_read()` и `block_write()`:

```c
uint8_t data[16] = "hello, sector 1";
if (proto->block_write(proto, 5, data, 16) == 0 && proto->block_read(proto, 5, data, sizeof(data))) {
    /* written and read back */
}
```

`block_write()` с 16 байтами отправляет MIFARE WRITE (A0h) одного блока и возвращает 0 или отрицательное значение,
если карта не подтвердила запись. Для блока другого сектора сначала нужна аутентификация этого сектора.

### Блоки значения

Блок значения хранит знаковое 32-битное значение трижды, из них один раз инвертированным, и байт адреса четыре раза,
из них дважды инвертированным; карта проверяет формат и сама прибавляет, вычитает и копирует значения, программе не
нужно их читать. Подключите `pn5180-mifare.h`:

```c
#include "pn5180-mifare.h"

/* sector of block 5 authenticated with a key that allows the operations */
pn5180_mifare_value_write(pn5180, 5, 100, 5);   /* value 100, address byte 5 */
pn5180_mifare_decrement(pn5180, 5, 30);         /* 70 into the transfer buffer of the card */
pn5180_mifare_transfer(pn5180, 5);              /* stored */

int32_t value;
if (pn5180_mifare_value_read(pn5180, 5, &value)) {
    printf("value %ld\n", (long)value);         /* 70 */
}
```

`pn5180_mifare_increment()`, `pn5180_mifare_decrement()` и `pn5180_mifare_restore()` кладут результат в буфер
передачи карты; `pn5180_mifare_transfer()` сохраняет его в блок — тот же или другой блок сектора.
`pn5180_mifare_value_read()` не читает блок, который не является правильно оформленным блоком значения. Какой ключ что
может делать, задают биты доступа в трейлере сектора.

## Ultralight и NTAG

Память из страниц по 4 байта, у большинства из них чтение без аутентификации:

- Страницы 0–2 хранят UID и статические байты блокировки, страница 3 — capability container (однократно
  программируемый), пользовательская память начинается со страницы 4. Последние страницы NTAG хранят конфигурацию и
  динамические байты блокировки.
- `block_read(proto, page, buf, len)` отправляет READ (30h): карта отвечает 16 байтами, четырьмя страницами начиная с
  `page`, и копируются первые `len` байт. У конца памяти чтение продолжается со страницы 0.
- `block_write(proto, page, buf, 4)` записывает одну страницу командой WRITE (A2h).
- `blocks_count` — число страниц, `block_size` равен 4.
- Биты блокировки и однократно программируемые биты нельзя сбросить: запись в страницу 2 или 3 или в динамические
  байты блокировки необратима.
- `authenticate()` возвращает `true` и ничего не отправляет. Пароль NTAG (PWD_AUTH) и аутентификация 3DES у
  Ultralight C не реализованы; если они нужны, их отправляют через `pn5180_rf_transceive()`.

```c
uint8_t pages[16];
if (proto->block_read(proto, 4, pages, sizeof(pages))) {  /* pages 4 to 7 */
    ESP_LOG_BUFFER_HEX(TAG, pages, sizeof(pages));
}
const uint8_t page[4] = {0x01, 0x02, 0x03, 0x04};
proto->block_write(proto, 4, page, sizeof(page));
```

NDEF на этих метках читают и пишут [функции NDEF](ndef.md): они знают, где лежит сообщение.

## Карты с MIFARE Classic и ISO14443-4 сразу

Некоторые карты (SmartMX, JCOP и подобные) эмулируют MIFARE Classic поверх чипа ISO14443-4 и сообщают SAK `28` (1K)
или `38` (4K). За одну активацию можно работать только с одной из двух сторон: после RATS карта говорит на ISO14443-4
и отвергает команды MIFARE, пока её не выберут заново.

Такая карта определяется с подтипом Classic и по умолчанию считается картой Classic: `select_by_uid()` не отправляет
RATS, поэтому аутентификация, доступ к блокам и `pn5180_ndef_read_card_auto()` работают как на настоящей карте
Classic.

Чтобы вместо этого работать со стороной ISO14443-4, перед выбором поменяйте подтип в своей копии `pn5180_uid_t`:

```c
pn5180_uid_t card = cards->uids[0];
if ((card.sak & 0x20) != 0) {              /* ISO14443-4 capable */
    card.subtype = PN5180_MIFARE_DESFIRE;  /* treat as ISO14443-4 / Type 4 */
}
if (proto->select_by_uid(proto, &card)) {
    /* pn5180_14443_4_transceive(), pn5180_14443_4_select_file(), ... */
}
```

С этим подтипом `detect_card_type_and_capacity()` его не меняет, а `pn5180_ndef_read_card_auto()` идёт по пути Type 4.
Чтобы переключить сторону у выбранной карты, вызовите `halt()` и `select_by_uid()` с другим подтипом.

## Свои кадры

`pn5180_rf_transceive()` отправляет выбранной карте любой кадр и принимает ответ. После `select_by_uid()` CRC включён в
обе стороны, поэтому команда карты отправляется как есть:

```c
const uint8_t read_sig[2] = {0x3C, 0x00};   /* NTAG READ_SIG */
uint8_t       sig[32];
size_t        got = 0;
pn5180_rf_result_t r = pn5180_rf_transceive(pn5180, read_sig, sizeof(read_sig), 0, sig, sizeof(sig), &got,
                                            10000 /* us */, NULL);
if (r == PN5180_RF_OK && got == 32) {
    ESP_LOG_BUFFER_HEX(TAG, sig, got);
}
```

Для кадра с неполным последним байтом, например 7-битного REQA, число значащих битов этого байта передаётся в
`tx_last_bits`; CRC включают и выключают `pn5180_enable_crc()` и `pn5180_disable_crc()`. См.
[справочник API](api.md#pn5180_rf_transceive).
