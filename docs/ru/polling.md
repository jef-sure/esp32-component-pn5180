# Поиск карт

*[In English](../en/polling.md)*

Опрос возвращает все карты в поле, а не только первую. Эта страница — об опросах: что они возвращают, как находятся
несколько карт, как устроен цикл опроса и что делать с телефонами, у которых меняется UID.

## Опрос

```c
pn5180_poll_status_t status;
pn5180_uids_array_t *cards = pn5180_14443_get_all_uids_ex(proto, &status);
switch (status) {
case PN5180_POLL_FOUND:
    for (int i = 0; i < cards->uids_count; i++) {
        pn5180_uid_t *card = &cards->uids[i];
        if (!proto->select_by_uid(proto, card)) {
            continue;
        }
        int blocks = 0, block_size = 0;
        if (proto->detect_card_type_and_capacity(proto->pn5180, card, &blocks, &block_size)) {
            proto->select_by_uid(proto, card);
        }
        printf("SAK %02X ATQA %02X%02X type %d: %d blocks of %d bytes\n", card->sak, card->atqa[0], card->atqa[1],
               card->subtype, blocks, block_size);
        proto->halt(proto);
    }
    free(cards);
    break;
case PN5180_POLL_NO_TARGET:
    break; /* nothing in the field */
case PN5180_POLL_TRANSPORT_ERROR:
    pn5180_recover(proto->pn5180);
    break;
default:
    break; /* a card answered but could not be singled out; try again */
}
```

`pn5180_14443_get_all_uids_ex()` и `pn5180_15693_get_all_uids_ex()` возвращают массив карт и статус. Колбэк
`get_all_uids()` объекта протокола — тот же опрос без статуса: он возвращает `NULL` при любом исходе, кроме
`PN5180_POLL_FOUND`.

Массив выделяется в куче; освобождает его `free()`. При статусе `PN5180_POLL_FOUND` `cards->uids_count` не меньше 1.

Карты возвращаются в том порядке, в каком найдены, а у ISO14443A он меняется от опроса к опросу. Метки ISO15693
отсортированы по силе сигнала, сильнейшая первой (наименьший `agc`).

## Статус опроса

| Статус | ISO14443A | ISO15693 |
| ------ | --------- | -------- |
| `PN5180_POLL_FOUND` | хотя бы одна карта; массив возвращается | то же |
| `PN5180_POLL_NO_TARGET` | ни одна карта не ответила | ни одна метка не ответила, или пришли только повреждённые ответы или ответы с коллизией |
| `PN5180_POLL_TRANSPORT_ERROR` | PN5180 не удалось управлять: сбой SPI, поле не включилось | то же |
| `PN5180_POLL_PROTOCOL_ERROR` | карта ответила, но антиколлизия или выбор не удались | никогда |
| `PN5180_POLL_NO_MEMORY` | не удалось выделить массив | то же |
| `PN5180_POLL_INVALID_ARGUMENT` | объект протокола или устройство — `NULL` | то же |

У опроса ISO15693 нет `PN5180_POLL_PROTOCOL_ERROR`: ответы, которые пришли повреждёнными или столкнулись и не
разрешились, дают `PN5180_POLL_NO_TARGET`, потому что PN5180 сообщает о шуме точно так же и такой ответ не доказывает,
что метка есть.

Если опрос нашёл часть карт, а потом наткнулся на ошибку, он возвращает найденные карты с `PN5180_POLL_FOUND`; статусы
ошибок приходят только с пустым результатом.

## Несколько карт в поле

Число карт ограничивает не протокол, а драйвер, чтобы карта, которая ведёт себя неправильно, не могла затягивать опрос
без конца. Опрос, который остановился на пределе, пишет в лог предупреждение и всё равно возвращает `PN5180_POLL_FOUND`
с найденными картами.

### ISO14443A

Опрос посылает REQA, разрешает один UID на всех его уровнях каскада, останавливает эту карту командой HLTA и снова
посылает REQA, пока карты не перестанут отвечать. Каждая карта стоит около 8 кадров RF и одного `pn5180_uid_t` в куче.

- **Предел** — `max_cards` из `pn5180_14443_init()`, 14, если там 0. Предупреждение появляется, только если
  действительно ответила ещё одна карта; ей посылают HLTA, который возвращает невыбранную карту в IDLE, чтобы она
  ответила на следующий опрос.
- **Карта, которая отвечает снова** после своего HLTA (кадр потерялся), останавливается ещё раз; второй такой повтор
  завершает опрос, так что карта, которая не слушается HLTA, не может затягивать его.
- **Неудачная антиколлизия** возвращает карты в IDLE командой HLTA; опрос возвращает карты, найденные до неё, или
  `PN5180_POLL_PROTOCOL_ERROR`, если их нет.
- `agc` каждого элемента читается сразу после того, как разрешён UID его карты.

### ISO15693

Опрос — это инвентаризация с маской: драйвер спрашивает только те метки, у которых младшие биты UID совпадают с маской,
а при коллизии удлиняет маску на один бит и пробует оба значения этого бита. Каждой найденной метке посылается Stay
Quiet, чтобы она больше не отвечала.

- **Предел** — 192 кадра инвентаризации, этого хватает примерно на 50 меток с непохожими UID. Метки, которые различаются
  только последними битами UID, требуют больше кадров каждая: две метки, которые различаются только последним битом,
  занимают 129.
- **Метка за более сильной.** Приёмник принимает ответ, который больше чем вдвое слабее другого, за отсутствие сигнала
  (техническое описание PN5180), так что метка вдали от антенны находится, только когда более близкие метки замолчали.
  Поэтому за проходом, который нашёл метки, следует ещё одна инвентаризация всего поля; когда меток не осталось, она
  стоит одного кадра.
- **Модуляция.** Инвентаризация сначала идёт с ASK 10 % и переходит на ASK 100 %, только если ничего не нашла, так что
  сила сигнала у всех меток одного опроса измерена при одной конфигурации RF.

### Карты, пропущенные опросом

Если поле остаётся включённым, следующий опрос находит пропущенные карты: найденные раньше остановлены или молчат
и больше не отвечают. Для ISO15693 это верно, пока найденные метки молчат: `select_by_uid()` и `halt()` возвращают метку
в Ready, и следующий опрос считает её снова; это важно, только когда меток в поле больше, чем берёт один опрос.

После сброса поля снова отвечают все карты: ISO14443A разрешает коллизии случайным образом, так что за несколько опросов
появляется каждая карта, хотя и не одинаково часто, а ISO15693 снова находит те же метки.

## Цикл опроса

То, что цикл делает между опросами, решает, какие карты вернёт каждый опрос.

**Все карты на каждом проходе.** Перед каждым опросом поле сбрасывают, чтобы карты, остановленные прошлым проходом,
ответили снова:

```c
pn5180_set_rf_off(pn5180);
pn5180_delay_us(PN5180_RF_OFF_TIME_US); /* 5.1 ms */
proto->setup_rf(proto);
pn5180_uids_array_t *cards = pn5180_14443_get_all_uids_ex(proto, &status);
```

**Только новые карты.** Если оставить поле включённым, карта, которая остаётся в поле, не возвращается снова, пока не
уйдёт и не вернётся или пока поле не сбросят:

- ISO14443A: `setup_rf()` при уже загруженной собственной конфигурации протокола оставляет поле включённым. Карта,
  которую выбрали и остановили, снова остановлена и в следующий опрос не попадает.
- ISO15693: `get_all_uids()` вызывают без `setup_rf()` между опросами. Инвентаризация загружает свою конфигурацию
  (ASK 10 %, см. выше) и оставляет поле, если та уже загружена, а `setup_rf()` загружает конфигурацию, переданную
  в `pn5180_15693_init()`, и, если это другая конфигурация, выключает и включает поле. Метка, которую выбрали или
  остановили командой Reset to Ready, снова в состоянии Ready, и опрос возвращает её опять.

**Оба протокола.** Протоколы опрашивают один за другим. `setup_rf()` другого протокола сам выключает поле на 5,1 мс,
поэтому оба опроса начинаются с карт в состоянии покоя:

```c
iso14443->setup_rf(iso14443);
pn5180_uids_array_t *a = iso14443->get_all_uids(iso14443);
/* ... */
iso15693->setup_rf(iso15693);
pn5180_uids_array_t *v = iso15693->get_all_uids(iso15693);
/* ... */
```

**Пауза между проходами.** Для неё подходит `vTaskDelay()`: она отпускает процессор на всю паузу. Если на время долгой
паузы выключать поле, это экономит энергию и не мешает другим считывателям рядом; [обнаружение карты с малым
потреблением](hardware.md#обнаружение-карты-с-малым-потреблением) у PN5180 может разбудить программу, когда карта
приблизится.

**Ошибки.** `PN5180_POLL_TRANSPORT_ERROR` значит, что PN5180 не ответил: нужно вызвать `pn5180_recover()`, которая
сбрасывает его и восстанавливает конфигурацию RF и поле. `PN5180_POLL_PROTOCOL_ERROR` обычно значит, что карты ответили
одновременно и одна из них сдвинулась; следующий опрос пробует снова.

## Цели со случайным UID

Телефон в режиме эмуляции карты и некоторые карты отвечают случайным 4-байтным UID, первый байт которого `08`,
и выбирают новый, когда ВЧ-поле появляется снова (ISO/IEC 14443-3). Такой UID опознаёт цель только до выключения поля:

- Цель выбирают и используют в том опросе, который её нашёл, пока поле не выключилось.
- После того как поле выключали (`setup_rf()` другого протокола, `pn5180_set_rf_off()`, `pn5180_recover()`), цель
  возвращается под другим UID. Сохранённый раньше `pn5180_uid_t` больше ничему не соответствует: `select_by_uid()`
  возвращает для него `false`, как и вторая попытка `pn5180_ndef_read_card_auto()`, если ей приходится выбирать карту
  заново. Нужно опросить снова и взять новый элемент.
- Такой UID нельзя использовать как идентификатор: тот же телефон после каждого цикла поля появляется как новая карта.

```c
bool random_uid = card->uid_length == 4 && card->uid[0] == 0x08;
```

Телефон — цель ISO14443-4: после `select_by_uid()` он говорит на APDU, а его сообщение NDEF, если приложение эмулирует
метку Type 4, читает `pn5180_ndef_read_card_auto()`. См. [ISO14443-4 и APDU](iso14443-4.md).
