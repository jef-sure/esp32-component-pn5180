# ISO15693 tags

*[По-русски](../ru/iso15693.md)*

Vicinity tags such as ICODE SLIX, SLIX2, DNA and the tags of many libraries and laundries: a longer range than
ISO14443A, memory of blocks, no authentication in this driver.

```c
#include "pn5180-15693.h"

pn5180_proto_t *tags = pn5180_15693_init(pn5180, PN5180_15693_26KASK100);
tags->setup_rf(tags);

pn5180_uids_array_t *found = tags->get_all_uids(tags);
if (found != NULL && tags->select_by_uid(tags, &found->uids[0])) {
    int blocks = 0, block_size = 0;
    tags->detect_card_type_and_capacity(pn5180, &found->uids[0], &blocks, &block_size);
    uint8_t data[32];
    if (block_size <= (int)sizeof(data) && tags->block_read(tags, 0, data, block_size)) {
        ESP_LOG_BUFFER_HEX(TAG, data, block_size);
    }
    tags->halt(tags);
}
free(found);
```

## RF configuration

`pn5180_15693_init()` takes the RF configuration that `setup_rf()` loads: `PN5180_15693_26KASK100` (26 kbit/s, ASK
100 %) or `PN5180_15693_26KASK10` (ASK 10 %). `PN5180_15693_26KASK100` suits most tags.

The inventory does not depend on that choice: it runs with ASK 10 % first, which keeps the tags better supplied during
the modulation, and falls back to ASK 100 % only when it found nothing. The configuration it ended with stays loaded,
and select, read and write use it.

After the field is switched on the driver waits its guard time, 5.1 ms by default. ISO15693 tags need 1 ms; a program
that polls only ISO15693 can shorten it with `pn5180_set_rf_guard_time_us(pn5180, 1000)`.

## Inventory

`get_all_uids()` and `pn5180_15693_get_all_uids_ex()` run an inventory with a mask, one slot per request: on a
collision the mask grows by one bit and both values are tried. Each tag found is sent Stay Quiet, so that it no longer
answers, and when a pass found tags the whole field is asked once more, so that a weak tag behind a strong one is found
too. The inventory stops after 192 frames, enough for about 50 tags with unrelated UIDs. Details are on
[Finding cards](polling.md#iso15693).

The entries come sorted by signal strength, the strongest first (the lowest `agc`). The UID has 8 bytes, least
significant first: `uid[7]` is `E0`, `uid[6]` the manufacturer code (04h for NXP).

The poll reports no `PN5180_POLL_PROTOCOL_ERROR`: answers that arrive damaged or collide without being resolved are
`PN5180_POLL_NO_TARGET`, because the PN5180 reports noise in the same way.

## Select, detect, halt

- `select_by_uid()` sends Select addressed to the UID of the entry; the tag goes to the Selected state, and the
  following commands are sent to the selected tag.
- `detect_card_type_and_capacity()` sends Get System Information and takes the number of blocks and the block size
  from the answer; `subtype` is `PN5180_15693`. A tag that does not answer it, or does not report its memory, gets
  `block_size` 4 and `blocks_count` 0. It returns `false`: no new select is needed.
- `halt()` sends Reset to Ready to the selected tag, which goes back to the Ready state. The command is optional in
  ISO15693: on a tag that does not implement it `halt()` returns `false`, and the tag stays selected until the field is
  switched off.

A tag in the Ready state answers the next inventory: a tag that was selected, or halted, is counted again by the next
poll, also with the field left on.

## Blocks

```c
const uint8_t block[4] = {0x11, 0x22, 0x33, 0x44};
if (tags->block_write(tags, 5, block, sizeof(block)) == 0) {
    uint8_t back[4];
    tags->block_read(tags, 5, back, sizeof(back));
}
```

- `block_read()` sends Read Single Block, or Extended Read Single Block for a block number above 255 (up to 65535). The
  tag has to deliver at least `buffer_len` bytes; pass the block size from the detection.
- `block_write()` sends Write Single Block, or the extended command above block 255, with 1 to 32 bytes. It returns 0
  when the tag confirmed the write, and a negative value otherwise. The tag answers after programming, which may take
  up to 20 ms.
- `authenticate` is `NULL` for ISO15693: password protection, privacy mode and the other custom commands of ICODE tags
  are not implemented. Send them with `pn5180_rf_transceive()` if you need them.

NDEF on an ISO15693 tag (NFC Forum Type 5) is read and written by [the NDEF functions](ndef.md): the capability
container in block 0, the TLVs after it.
