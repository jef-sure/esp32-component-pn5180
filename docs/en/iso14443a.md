# ISO14443A cards

*[По-русски](../ru/iso14443a.md)*

MIFARE Classic, MIFARE Plus, Ultralight, NTAG and ISO14443-4 cards: how the driver tells them apart, selects them,
authenticates and reads and writes their memory. ISO14443-4 cards and APDUs have [their own page](iso14443-4.md),
polling is on [Finding cards](polling.md).

```c
#include "pn5180-14443.h"

pn5180_proto_t *proto = pn5180_14443_init(pn5180, 0); /* 0: at most 14 cards per poll */
proto->setup_rf(proto);
```

## Card types

`detect_card_type_and_capacity()` takes the SAK of the selected card (bits 0 to 6) and, for the Ultralight family,
asks the card itself:

| SAK | `subtype` | `blocks_count` × `block_size` |
| --- | --------- | ----------------------------- |
| `00` | the Ultralight family, see below | pages of 4 bytes |
| `08` | `PN5180_MIFARE_CLASSIC_1K` | 64 × 16 |
| `09` | `PN5180_MIFARE_CLASSIC_MINI` | 20 × 16 |
| `10` | `PN5180_MIFARE_PLUS_2K` (security level 2) | 128 × 16 |
| `11` | `PN5180_MIFARE_PLUS_4K` (security level 2) | 256 × 16 |
| `18` | `PN5180_MIFARE_CLASSIC_4K` | 256 × 16 |
| `28` | `PN5180_MIFARE_CLASSIC_1K`, emulated on an ISO14443-4 card | 64 × 16 |
| `38` | `PN5180_MIFARE_CLASSIC_4K`, emulated on an ISO14443-4 card | 256 × 16 |
| `20`, or any other with bit `20` | `PN5180_MIFARE_DESFIRE`: an ISO14443-4 card | 0 × 1 |
| any other | `PN5180_MIFARE_UNKNOWN` | 0 × 0 |

`PN5180_MIFARE_DESFIRE` stands for every ISO14443-4 card, a DESFire, a bank card, a passport or a phone alike; the
driver does not tell them apart.

The Ultralight family shares SAK `00` and ATQA `44 00`. The driver sends GET_VERSION (60h) and reads the storage size
and the product type from the answer:

| GET_VERSION | `subtype` | pages |
| ----------- | --------- | ----- |
| storage `0B`, product NTAG | `PN5180_MIFARE_NTAG210` | 20 |
| storage `0B`, other product | `PN5180_MIFARE_ULTRALIGHT_EV1` (MF0UL11) | 20 |
| storage `0E`, product NTAG | `PN5180_MIFARE_NTAG212` | 41 |
| storage `0E`, other product | `PN5180_MIFARE_ULTRALIGHT_EV1` (MF0UL21) | 41 |
| storage `0F` | `PN5180_MIFARE_NTAG213` | 45 |
| storage `11` | `PN5180_MIFARE_NTAG215` | 135 |
| storage `13` | `PN5180_MIFARE_NTAG216` | 231 |
| another storage size | `PN5180_MIFARE_ULTRALIGHT` | 16 |
| no answer, the card answers AUTHENTICATE (1Ah) with a challenge | `PN5180_MIFARE_ULTRALIGHT_C` | 44 |
| no answer to either | `PN5180_MIFARE_ULTRALIGHT` | 16 |

A GET_VERSION answer that arrives damaged is asked for once more. A tag that does not answer GET_VERSION, the original
Ultralight or an NTAG203, is reported as `PN5180_MIFARE_ULTRALIGHT` with 16 pages; that is a guess, so the NDEF
functions take the size of its data area from the capability container alone. Of the 48 pages of an Ultralight C, the
44 that READ reaches are counted; the key pages 2Ch to 2Fh cannot be read.

The detection of the Ultralight family leaves the card halted, and `detect_card_type_and_capacity()` returns `true`:
select the card again before using it. For the other cards it returns `false` and the card stays selected.

```c
pn5180_uid_t *card = &cards->uids[i];
if (proto->select_by_uid(proto, card)) {
    int blocks = 0, block_size = 0;
    if (proto->detect_card_type_and_capacity(proto->pn5180, card, &blocks, &block_size)) {
        proto->select_by_uid(proto, card);
    }
    /* card->subtype, card->blocks_count and card->block_size are set */
}
```

## Selecting and halting

`select_by_uid()` sends WUPA, which wakes cards in the idle and in the halted state, then SELECT for each cascade level
with the UID of the entry. It updates `sak` and `atqa` of the entry. A card with SAK bit `20` is then activated as an
ISO14443-4 card (RATS), except a card that also emulates MIFARE Classic, see
[below](#cards-with-both-mifare-classic-and-iso14443-4).

`halt()` sends HLTA, or S(DESELECT) to a card in its ISO14443-4 session. A halted card is found again by
`select_by_uid()`, but by a poll only after the field was switched off.

A selected card does not answer a new `select_by_uid()`: `halt()` it first. A card that refused a command is out of
the selected state: Ultralight and NTAG after any NAK (a read beyond the last page, a write to a locked page), MIFARE
Classic after a refused authentication. `halt()` and `select_by_uid()` again.

## MIFARE Classic

### Memory

A MIFARE Classic card is divided into sectors, each with its own keys:

| Card | Sectors | Blocks |
| ---- | ------- | ------ |
| Mini | 5 of 4 blocks | 0 to 19 |
| 1K | 16 of 4 blocks | 0 to 63 |
| 4K | 32 of 4 blocks, then 8 of 16 blocks | 0 to 127, 128 to 255 |

The last block of each sector is its trailer: key A, the access bits, the general purpose byte and key B. Block 0 is
the manufacturer block with the UID. Write a trailer only with access bits you have checked: wrong ones lock the sector
for good.

```c
static int first_block_of_sector(int sector)
{
    return sector < 32 ? sector * 4 : 128 + (sector - 32) * 16;
}
```

### Authentication

```c
static const uint8_t key[6] = {0xFF, 0xFF, 0xFF, 0xFF, 0xFF, 0xFF};

/* Card selected. Authentication is per sector: block 4 is the first block of sector 1. */
if (proto->authenticate(proto, key, PN5180_MIFARE_CLASSIC_KEYA, card, 4)) {
    uint8_t data[16];
    if (proto->block_read(proto, 4, data, sizeof(data))) {
        ESP_LOG_BUFFER_HEX(TAG, data, sizeof(data));
    }
}
```

- `key_type` is `PN5180_MIFARE_CLASSIC_KEYA` (60h) or `PN5180_MIFARE_CLASSIC_KEYB` (61h); the block number, 0 to 255,
  names the sector. A 7- or 10-byte UID authenticates with its last 4 bytes.
- After a failed authentication the card stops answering: select it again (`halt()`, then `select_by_uid()`) before
  trying another key.
- Try one key per authentication; asking the same key again after a refusal only costs time. A card that did not
  answer has left the field, and the next key would not reach it either.
- For Ultralight, NTAG and ISO14443-4 cards `authenticate()` returns `true` at once and sends nothing. MIFARE Plus
  cards are sent the same Crypto1 authentication as Classic cards.

`pn5180->iso14443_last_auth_status` tells why an authentication failed:

| Value | Meaning |
| ----- | ------- |
| `PN5180_MIFARE_AUTH_OK` (0) | the key was accepted |
| `PN5180_MIFARE_AUTH_REFUSED` (1) | the card turned the key down |
| `PN5180_MIFARE_AUTH_NO_ANSWER` (2) | the card did not answer: it left the field, or was not selected |
| `PN5180_MIFARE_AUTH_NONE` (-1) | nothing was sent: a block number or UID length the protocol does not know |

A search through a list of keys, as `examples/app_logic` does it:

```c
static bool try_keys(pn5180_proto_t *proto, pn5180_uid_t *card, int block,
                     const uint8_t (*keys)[6], size_t key_count)
{
    for (size_t k = 0; k < key_count; k++) {
        for (uint8_t type = PN5180_MIFARE_CLASSIC_KEYA; type <= PN5180_MIFARE_CLASSIC_KEYB; type++) {
            if (proto->authenticate(proto, keys[k], type, card, block)) {
                return true;
            }
            if (proto->pn5180->iso14443_last_auth_status != PN5180_MIFARE_AUTH_REFUSED) {
                return false; /* the card is gone */
            }
            if (!proto->select_by_uid(proto, card)) {
                return false;
            }
        }
    }
    return false;
}
```

### Blocks

After the authentication of a sector, `block_read()` and `block_write()` work on its blocks:

```c
uint8_t data[16] = "hello, sector 1";
if (proto->block_write(proto, 5, data, 16) == 0 && proto->block_read(proto, 5, data, sizeof(data))) {
    /* written and read back */
}
```

`block_write()` with 16 bytes sends the MIFARE WRITE (A0h) of one block and returns 0, or a negative value when the
card did not acknowledge it. A block of another sector needs that sector's authentication first.

### Value blocks

A value block holds a signed 32-bit value three times, once inverted, and an address byte four times, twice inverted;
the card checks the format and adds, subtracts and copies values without the program reading them. Include
`pn5180-mifare.h`:

```c
#include "pn5180-mifare.h"

/* sector of block 5 authenticated with a key that allows the operations */
pn5180_mifare_value_write(pn5180, 5, 100, 5);   /* value 100, address byte 5 */
pn5180_mifare_decrement(pn5180, 5, 30);         /* 70 into the transfer buffer of the card */
pn5180_mifare_transfer(pn5180, 5);              /* stored */

int32_t value;
if (pn5180_mifare_value_read(pn5180, 5, &value)) {
    printf("value %ld\n", (long)value);         /* 70 */
}
```

`pn5180_mifare_increment()`, `pn5180_mifare_decrement()` and `pn5180_mifare_restore()` put their result into the
card's transfer buffer; `pn5180_mifare_transfer()` stores it into a block, the same or another one of the sector.
`pn5180_mifare_value_read()` fails for a block that is not a correctly formatted value block. Which key may do what is
set by the access bits of the sector trailer.

## Ultralight and NTAG

Memory of 4-byte pages, no authentication for reading on most of them:

- Pages 0 to 2 hold the UID and the static lock bytes, page 3 the capability container (one-time programmable), the
  user memory starts at page 4. The last pages of an NTAG hold the configuration and the dynamic lock bytes.
- `block_read(proto, page, buf, len)` sends READ (30h): the card answers with 16 bytes, four pages from `page` on, and
  the first `len` bytes are copied. Near the end of the memory the read wraps to page 0.
- `block_write(proto, page, buf, 4)` writes one page with WRITE (A2h).
- `blocks_count` is the number of pages, `block_size` is 4.
- Lock bits and one-time programmable bits cannot be cleared: a write to page 2 or 3, or to the dynamic lock bytes,
  is for good.
- `authenticate()` returns `true` and sends nothing. The password of an NTAG (PWD_AUTH) and the 3DES authentication of
  the Ultralight C are not implemented; send them with `pn5180_rf_transceive()` if you need them.

```c
uint8_t pages[16];
if (proto->block_read(proto, 4, pages, sizeof(pages))) {  /* pages 4 to 7 */
    ESP_LOG_BUFFER_HEX(TAG, pages, sizeof(pages));
}
const uint8_t page[4] = {0x01, 0x02, 0x03, 0x04};
proto->block_write(proto, 4, page, sizeof(page));
```

NDEF on these tags is read and written by [the NDEF functions](ndef.md), which know where the message lies.

## Cards with both MIFARE Classic and ISO14443-4

Some cards (SmartMX, JCOP, and similar) emulate MIFARE Classic on top of an ISO14443-4 chip and report SAK `28` (1K)
or `38` (4K). One activation can serve only one of the two sides: once RATS was sent, the card speaks ISO14443-4 and
refuses MIFARE commands until it is selected anew.

Such a card is detected with a Classic subtype and is treated as Classic by default: `select_by_uid()` does not send
RATS, so authentication, block access and `pn5180_ndef_read_card_auto()` work as on a native Classic card.

To use the ISO14443-4 side instead, change the subtype in your copy of the `pn5180_uid_t` before selecting:

```c
pn5180_uid_t card = cards->uids[0];
if ((card.sak & 0x20) != 0) {              /* ISO14443-4 capable */
    card.subtype = PN5180_MIFARE_DESFIRE;  /* treat as ISO14443-4 / Type 4 */
}
if (proto->select_by_uid(proto, &card)) {
    /* pn5180_14443_4_transceive(), pn5180_14443_4_select_file(), ... */
}
```

With that subtype `detect_card_type_and_capacity()` keeps it, and `pn5180_ndef_read_card_auto()` takes the Type 4
path. To switch sides on a selected card, call `halt()` and `select_by_uid()` with the other subtype.

## Frames of your own

`pn5180_rf_transceive()` sends any frame to the selected card and receives the answer. After `select_by_uid()` the
CRC is on in both directions, so a command of the card is sent as it is:

```c
const uint8_t read_sig[2] = {0x3C, 0x00};   /* NTAG READ_SIG */
uint8_t       sig[32];
size_t        got = 0;
pn5180_rf_result_t r = pn5180_rf_transceive(pn5180, read_sig, sizeof(read_sig), 0, sig, sizeof(sig), &got,
                                            10000 /* us */, NULL);
if (r == PN5180_RF_OK && got == 32) {
    ESP_LOG_BUFFER_HEX(TAG, sig, got);
}
```

A frame whose last byte is not complete, such as the 7-bit REQA, passes the number of valid bits of that byte in
`tx_last_bits`; the CRC is switched with `pn5180_enable_crc()` and `pn5180_disable_crc()`. See
[the API reference](api.md#pn5180_rf_transceive).
