# ISO14443-4 and APDUs

*[По-русски](../ru/iso14443-4.md)*

DESFire, bank cards, passports, JCOP and other smart cards, and phones in card emulation speak ISO14443-4 (ISO-DEP):
the reader sends command APDUs (ISO 7816-4) and the card answers with response APDUs. The driver works in reader mode
only; card emulation and peer-to-peer are not implemented.

```c
#include "pn5180-14443.h"
```

## Activation

An ISO14443-4 card is found by the [ISO14443A poll](polling.md) like any other; its SAK has bit `20` set, and
`detect_card_type_and_capacity()` reports it as `PN5180_MIFARE_DESFIRE`, whatever card it is. `select_by_uid()`
activates the ISO14443-4 layer itself with RATS:

- the answer (ATS) gives the largest frame the card accepts (FSCI), its frame waiting time (FWI) and its start-up
  frame guard time (SFGI);
- the driver waits the start-up frame guard time before the first block;
- a reserved FWI 15 is read as the default 4, a reserved SFGI 15 as 0, a reserved FSCI as the largest frame size.

A card that also emulates MIFARE Classic (SAK `28` or `38`) is not activated unless the program asks for it, see
[Cards with both MIFARE Classic and ISO14443-4](iso14443a.md#cards-with-both-mifare-classic-and-iso14443-4).

## Exchanging APDUs

```c
const uint8_t apdu[] = {0x90, 0x60, 0x00, 0x00, 0x00}; /* DESFire GetVersion */
uint8_t       rx[64];
size_t        rx_len = sizeof(rx);
if (pn5180_14443_4_transceive(pn5180, apdu, sizeof(apdu), rx, &rx_len)) {
    pn5180_apdu_response_t response;
    pn5180_apdu_parse_response(rx, rx_len, &response);
    printf("SW %04X, %u data bytes\n", pn5180_apdu_get_status(&response), (unsigned)response.data_len);
}
```

`pn5180_14443_4_transceive()` sends one command APDU and returns the whole response, data followed by SW1 SW2.
`rx_len` is the size of `rx` on the way in and the length of the response on the way out. Under it the driver:

- **chains** a command longer than the card's frame in several I-blocks, and collects a chained response, in
  blocks of at most 253 bytes;
- **waits** the frame waiting time of the ATS for each block, and grants waiting time extensions (S(WTX)) up to the
  longest frame waiting time the standard allows, about 5 s; a card that asks for more than 10 in a row is given up;
- **repeats** a block that got lost or arrived damaged, up to 3 times, with R(NAK) or by sending it again, as
  ISO/IEC 14443-4 describes.

`true` means that a response arrived; the status word inside it says whether the card did what it was asked. A
failed exchange (no answer after the retries, a protocol error, a response larger than `rx`) ends the session: the
driver sends S(DESELECT), and the card has to be selected again with `select_by_uid()` before the next APDU. If the card
does not react to that either, switch the field off and on.

`halt()` releases the card with S(DESELECT). A card left in its session would answer the I-blocks meant for the next
card, so `select_by_uid()` and the poll close such a session themselves first.

## SELECT and READ BINARY

Two commands of ISO 7816-4 have helpers, because the NDEF code uses them:

```c
static const uint8_t ndef_app[] = {0xD2, 0x76, 0x00, 0x00, 0x85, 0x01, 0x01};
static const uint8_t cc_file[]  = {0xE1, 0x03};

if (pn5180_14443_4_select_file(pn5180, ndef_app, sizeof(ndef_app)) &&
    pn5180_14443_4_select_file(pn5180, cc_file, sizeof(cc_file))) {
    uint8_t cc[15];
    size_t  got = sizeof(cc);
    if (pn5180_14443_4_read_binary(pn5180, 0, sizeof(cc), cc, &got)) {
        ESP_LOG_BUFFER_HEX(TAG, cc, got);
    }
}
```

- `pn5180_14443_4_select_file()` selects an application by AID when it is given more than two bytes (P1 04h), or an
  elementary file by its identifier (P1 00h, P2 0Ch, no answer data), as NFC Forum Type 4 mapping 2.0 asks. A card
  that refuses the file select with an error status word is asked once more with P2 00h, for mapping 1.0 cards. It
  returns `true` for the answer `90 00`.
- `pn5180_14443_4_read_binary()` reads from the selected file: `offset` up to 7FFFh, `le` the number of bytes asked
  for, 0 meaning 256. `got` is the size of the buffer on the way in and the number of bytes on the way out; when the
  answer does not fit, the function returns `false` and `got` holds the size it needed.

## block_read on an ISO14443-4 card

For an ISO14443-4 card the `block_read` callback is READ BINARY on the file the program selected last, with the
block number as the offset in the file and `buffer_len` (1 to 255) as Le. It fails when the card returns fewer bytes
than the buffer asks for, at the end of the file for example.

`block_write` is not available for such a card: it would send MIFARE frames, which do not belong in an ISO14443-4
session, so it returns -1 and sends nothing. Write with an UPDATE BINARY APDU through `pn5180_14443_4_transceive()`
instead. `authenticate` returns `true` and does nothing; the authentication of DESFire and other cards is a sequence of
APDUs of the card's own command set, not implemented here.

## The APDU utilities

Independent of the PN5180 and of any card, these parse and build APDUs in memory of the caller and allocate nothing;
the parsed data pointers point into the input buffer.

```c
pn5180_apdu_command_t cmd;
const uint8_t raw[] = {0x00, 0xA4, 0x04, 0x00, 0x07, 0xD2, 0x76, 0x00, 0x00, 0x85, 0x01, 0x01, 0x00};
if (pn5180_apdu_parse_command(raw, sizeof(raw), &cmd) == ESP_OK) {
    /* cmd.ins == 0xA4, cmd.data_len == 7, cmd.has_le, cmd.le == 256 */
}

uint8_t out[32];
size_t  out_len;
pn5180_apdu_build_response(out, sizeof(out), (const uint8_t *)"OK", 2, 0x90, 0x00, &out_len); /* 4F 4B 90 00 */
```

- `pn5180_apdu_parse_command()` takes short APDUs of cases 1, 2S, 3S and 4S; an extended-length APDU is
  `ESP_ERR_NOT_SUPPORTED`, a malformed one `ESP_ERR_INVALID_ARG`. An encoded Le of 0 is reported as 256.
- `pn5180_apdu_parse_response()` splits a response into its data and SW1 SW2; `pn5180_apdu_get_status()` returns them
  as one 16-bit status word.
- `pn5180_apdu_build_response()` writes `DATA SW1 SW2` into a buffer; `ESP_ERR_NO_MEM` when it is too small.
- Status word constants: `PN5180_APDU_SW_SUCCESS` (9000h), `PN5180_APDU_SW_WRONG_LENGTH` (6700h),
  `PN5180_APDU_SW_WRONG_P1P2` (6A86h), `PN5180_APDU_SW_INS_NOT_SUPPORTED` (6D00h),
  `PN5180_APDU_SW_CLA_NOT_SUPPORTED` (6E00h).

## Phones

A phone in card emulation is an ISO14443-4 target with a [random UID](polling.md#targets-with-a-random-uid): select and
use it in the scan that found it. An app on the phone answers the AIDs it registered; one that emulates an NFC Forum
Type 4 tag is read by `pn5180_ndef_read_card_auto()` like a card, see [NDEF](ndef.md).
